# LeakSanitizer suppressions for leaks that are NOT in our code.
#
# Use:  LSAN_OPTIONS=suppressions=tools/lsan-suppressions.txt ./build-asan/...
#
# Every entry names a third-party function and why it's here. Never add a
# pattern that could match our own code (src/, deps/common/, deps/libretro/).

# SDL3's X11 driver: the X input method (XOpenIM / XIM) and XRandR lookups made
# during SDL_Init are never freed by Xlib. Seen on Xvfb and X11 sessions, also
# in piccolo with nothing but SDL_Init + SDL_Quit.
leak:X11_InitIM
leak:X11_GetGlobalContentScale
leak:X11_AddXRandRDisplay

# Known and NOT suppressible: with Mesa's software Vulkan driver (lavapipe /
# llvmpipe) LeakSanitizer reports 2 x 56 bytes from a driver thread. The driver
# is unloaded by vkDestroyInstance, so its frames show as "<unknown module>" and
# can't be matched here. Piccolo (no core, no host) shows the same 112 bytes.

# OpenGL ES (the GL path): Mesa's libEGL allocates 392 bytes while SDL
# loads it (eglGetDisplay inside SDL_EGL_LoadLibrary) and never frees them,
# even after eglTerminate. Seen on Wayland with panfrost (frontend_gl_video;
# piccolo's file has the same line).
leak:SDL_EGL_LoadLibrary

# SDL3's ALSA driver with no sound card (CI runners): libasound builds its
# config tree (snd_config_update) while SDL looks for a device and keeps it
# for the process, even when the open fails. Seen in piccoletto_hosts, whose
# client opens the audio when the stream's first audio packet arrives.
leak:ALSA_guess_device_prefix
leak:ALSA_OpenDevice
